PI EXPLORER / VERSION 1.4 / FRESH NATIVE TUNING

The native arithmetic remains multithreaded Chudnovsky. There is no claim of
a new mathematical algorithm, a universal fastest implementation, or a
billion-digit calculation completed within 30 seconds on this computer.

Changes:
- Use the native program's SSD configuration on this NVMe-backed installation:
  2 lanes x 2 workers, 1 MiB buffers (4 MiB total), parallel read/write tuning.
  The previous CLI defaults used one 64 MiB buffer without parallel access.
- Omit unused native checkpoint copies. The wrapper never resumed those
  checkpoints and always cleared scratch at cancellation. Arithmetic checking,
  decimal-output verification, raw I/O and disk checksums remain enabled.
- The calculator supervisor now imports only standard-library modules. It
  does not import the GMP/NumPy math and conversion stack into another process.
- Scratch monitoring tolerates native files being replaced while sampled.
  Cleanup retries briefly while terminated native I/O handles are closing.
- Tune CPU task placement with actual fresh calculations. Apply the measured
  small-run affinity profile through 25M digits on the matching CPU. Larger
  runs retain native CPU scheduling with the SSD I/O configuration.

Corrected comparison: two fresh 25M calculations for each configuration,
128 MiB working-memory setting. All eight complete outputs matched the first
25M digits of the independently performed, verified 200M cache. No digit
cache was used in place of fresh calculation.

Median native verified wall time (includes native output checks and cleanup;
excludes the Windows approval prompt and full app startup/cache commit):
  Legacy disk defaults:   9.8675 seconds  (individual runs: 12.844, 6.891)
  SSD, native threads:    8.1410 seconds  (individual runs: 8.985, 7.297)
  SSD, P-core threads:    7.1175 seconds  (individual runs: 7.000, 7.235)
  SSD, physical threads: 10.0160 seconds  (individual runs: 11.000, 9.032)

The selected small-run median is about 28% shorter than the legacy median.
Background load and timing variation are substantial; this is not a promise
that every calculation is faster by that amount. Large-run thread placement
is not inferred from the small-run test.

The first tuning pass exposed a scratch-monitor race and a native config list
syntax issue. Both were fixed before the corrected comparison. A separate
